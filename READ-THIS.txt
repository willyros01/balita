WIRE v0.17.52 — FIXES THE WARNING ITSELF, WHICH NEVER ACTUALLY APPEARED

THREE FILES. Replace these on GitHub:
  sw.js
  app.js
  version.js

WHAT WAS ACTUALLY WRONG WITH v0.17.51
The warning added last time checked something called
getNotifications() to see how many alerts were already waiting. That
specific function is documented to always return an empty list on
iOS Safari - meaning the check could never have found anything on
your phone, no matter how many notifications genuinely were sitting
there. Not a mistake in the condition itself. The information it was
reading from was broken on this platform from the start.

THE FIX
Counting how many stories are already sitting in Wire's own durable
list - the one already proven solid throughout this entire project -
tells us the same thing reliably. Checked before the new notification's
own entry gets added, so it only counts what was genuinely already
there beforehand.

Re-tested all five real combinations against this corrected version
before packaging it - cold with none waiting, cold with several
waiting, already running with none, already running with one, already
running with several. The warning now appears only in the two
already-running cases with something else waiting, exactly as
intended, and stays silent in every other case, including every cold
start regardless of how many are waiting.
