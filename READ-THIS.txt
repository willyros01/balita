WIRE v0.17.48 — A SMALL, READABLE TRACE, FOCUSED ON THIS ONE QUESTION

THREE FILES. Replace these on GitHub:
  sw.js
  app.js
  version.js

WHAT THIS RECORDS
Not the full system from before - just what's needed to see plainly
whether the phone itself is handing over the wrong information for a
specific tap, or something in these files is. Every line is written
as a complete sentence, not a code fragment, so it can be read
directly.

The single most important line: the moment any notification is
tapped, it records exactly what the operating system itself says that
banner belongs to - the article id, the tag, the time it was
originally sent. Not what the app assumes. What the phone actually
hands over. If that line ever names the wrong article for a tap that
was clearly on a different banner, that points at something outside
these files entirely.

It also marks plainly, in words, whether each tap found the app
already open (a background-to-foreground resume) or found nothing
running at all (a cold start) - since that distinction mattered to
what you're checking.

WHERE TO READ IT
The About panel again has two small buttons at the bottom - Save
trace as a file, and Clear trace. Same as before: tap Clear trace
before a test, run the test, then Save trace as a file afterward and
send that file here.

HOW TO TEST
Same full routine as always - kill the app, delete the icon, add it
back fresh. Get three notifications waiting, tap the one that isn't
oldest or newest, save the trace, send it - whether it works this
time or not.
