WIRE v0.17.42 — CHECKS THE WRITE THE INSTANT IT HAPPENS

THREE FILES. Replace these on GitHub:
  sw.js
  app.js
  version.js

WHY THIS ONE IS DIFFERENT
Every background-resume test so far has come back with zero worker
activity in the trace at all - not written, not deleted, simply never
present. That leaves two real possibilities open: the write itself is
failing right there and then, or it succeeds and something clears it
before the tap happens minutes later. There has been no way to tell
those apart.

WHAT CHANGED
The instant the destination is written, this version reads the exact
same record straight back, in the same breath, before doing anything
else. Whatever that read-back finds is folded directly into the
notification's own visible text - the one channel that has worked
correctly on every single test so far, regardless of anything else
failing.

WHAT THE BANNER WILL SAY THIS TIME
If everything is fine, it looks completely normal, just the headline.

If the write itself failed outright, it will say:
  [write failed: <the actual error>]

If the write did not throw, but reading it back immediately afterward
still finds nothing there, it will say:
  [write did not verify]

Those are two different problems with two different fixes, and this is
the first time either has been possible to tell apart directly.

WHAT TO DO
One background test, either device. Look closely at the banner text
itself before tapping it, not just after. Save and send the trace too.
