WHY THIS ONE IS DIFFERENT
The iPhone's notification banner displays correctly - that's proven now,
twice. So the push itself is working. What's still unclear is whether
the one small file it's supposed to write alongside that banner is
failing to write at all, or writing fine and then being cleared before
the tap happens. Those need different fixes, and there was no way to
tell them apart before this.

WHAT CHANGED
If writing that file fails at the moment the notification arrives, the
banner's own text will now say so directly - something like:

  Some headline  [route write failed: <the actual error>]

If the banner looks completely normal, the write succeeded at that
moment. The trace will also separately record whether the write
attempted again at the tap itself succeeded or failed, which tells us
whether writing itself is broken on that device or something is
clearing a write that worked.

WHAT TO DO

at the banner text itself this time, not just the headline - if it
says anything after the headline in brackets, that is the direct
answer. Save and send the trace file either way.
