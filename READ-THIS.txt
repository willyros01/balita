WHAT WAS ACTUALLY WRONG
Not the notification handling. The recorder. Two events firing close
together - which a real notification and the check for it always do -
could each read the log before the other had finished writing it back,
and whichever wrote second silently erased the other's line. That is
almost certainly why some traces came back with only one line: not
because nothing else happened, but because this recorder lost the
evidence that it did.

Proven directly before shipping: the old design was made to fail with
the exact same timing a real device produces, and it lost a line every
time. The new design - each event writes to its own key instead of
sharing one - was run through the identical test and lost nothing, even
across the worker and the page writing at once.

WHAT THIS MEANS FOR THE LAST TWO TESTS
The iPhone trace showed a full, clean, complete success - that one is
real and can be trusted as is. The iPad trace showing only one line is
now suspect, not confirmed - it may well have been a real success or a
real failure, but this recorder's bug means we cannot tell from what it
produced. Worth testing the iPad again with this version before drawing
any conclusion from that one.
